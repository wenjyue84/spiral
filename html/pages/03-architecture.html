Phase Loop Overview

SPIRAL runs in a structured loop with 11 phases per iteration:

  1. Phase 0 (CLARIFY): Initial setup — constitution, focus, scope (startup only)
  2. Phase A (AI SUGGEST): Generate story candidates
  3. Phase R (RESEARCH): Web search for requirements (parallel with Phase T)
  4. Phase T (TEST SYNTH): Scan test failures for regression stories (parallel with Phase R)
  5. Phase S (STORY VALID): Validate stories against constitution
  6. Phase E (ENRICHMENT): Populate hints and context on stories
  7. Phase M (MERGE): Update prd.json with validated stories
  8. Phase X (CONTEXT BUILD): Dependency inference (optional)
  9. Phase G (GATE): Human checkpoint (skipped with --gate proceed)
  10. Phase I (IMPLEMENT): Ralph workers execute stories in parallel
  11. Phase V (VALIDATE): Run tests and quality gates
  12. Phase C (CHECK DONE): Assess completion and decide to continue

Key Components

All top-level components with their roles, file paths, and languages:

Name Role Path Language
spiral.sh Main orchestrator. Parses arguments, manages phase loop, coordinates workers, handles state recovery. spiral.sh Bash
ralph/ralph.sh Implementation worker. One invocation per story. Reads story from prd.json, calls Claude CLI, commits results. ralph/ralph.sh Bash
lib/run_parallel_ralph.sh Worker manager. Creates isolated git worktrees, distributes story slices, monitors worker progress. lib/run_parallel_ralph.sh Bash
lib/spiral/ Python modules for story management, validation, merging, deduplication, cost tracking, and analysis. lib/spiral/ Python
lib/phases/ Phase orchestration stubs. Delegates to spiral.sh or Python submodules. Migration target from monolithic spiral.sh. lib/phases/ Bash/Python
prd.json Product backlog. Contains all stories with status, priority, dependencies, and metadata. prd.json JSON
spiral-ui/ React dashboard at http://localhost:5299. Live monitoring of phases, stories, workers, token burn, results. spiral-ui/ React/TypeScript
.spiral-workers/ Directory containing isolated git worktrees for parallel workers. One per worker during Phase I. .spiral-workers/ Git

Data Flow

Configuration: spiral.config.sh → environment variables

Stories: prd.json → Phase M → Phase I (Ralph) → git commit → results.tsv

State: .spiral/_checkpoint.json (crash recovery), retry-counts.json, results.tsv (telemetry)

Parallel Workers

Phase I launches up to N workers (configurable, default 1). Each worker:

  • Gets an isolated git worktree at .spiral-workers/worker-N/
  • Receives a slice of prd.json with assigned stories
  • Runs ralph.sh for each story
  • Commits completed work back to main branch
