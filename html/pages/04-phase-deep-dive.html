Phase 0 — CLARIFY Startup only, interactive session

Summary

One-time interactive session that runs before the main loop begins. Establishes the project's constitution (non-negotiable rules), sets the session focus theme, clarifies scope via 3 targeted questions, collects initial story seeds, and configures session options (time limit, worker count).

Inputs

  • prd.json — Product requirements document to extract goals and epics
  • User interaction — Interactive prompts for constitution review, focus definition, clarifying questions, story seeds

Outputs

  • .spiral/_clarify_output.json — Audit log of session setup: constitution path, focus, time limit
  • .spiral/_phase_0_done — Marker file so resume skips Phase 0
  • Environment variables exported: SPIRAL_FOCUS, TIME_LIMIT_MINS, SPIRAL_SPECKIT_CONSTITUTION

Configuration Variables

  • SPIRAL_FOCUS — Session theme/context string set during Clarify phase
  • TIME_LIMIT_MINS — Maximum iteration duration in minutes (0 = unlimited)
  • SPIRAL_SPECKIT_CONSTITUTION — Path to constitution.md file

Implementing File

lib/phases/phase_0_clarify.sh

Phase A — AI SUGGEST Per-iteration story candidates

Summary

Generate AI-suggested story candidates by analyzing gaps in the PRD (missing user stories, incomplete epics) and scanning for test stories that could improve test coverage. Stories are marked with _source: "ai-example" for later prioritization.

Inputs

  • prd.json — Current PRD with goals, epics, and existing stories
  • results.tsv (optional) — Historical attempt data to identify patterns
  • Test files (optional) — Scan for untested code paths

Outputs

  • New story candidates with _source: "ai-example", estimatedComplexity, and description
  • Stories queued for Phase R research, Phase S validation, and Phase E enrichment

Configuration Variables

  • SPIRAL_MAX_PENDING — Maximum pending stories to hold before merge (default 20)
  • SPIRAL_STORY_BATCH_SIZE — Stories to generate per iteration (default 5)

Implementing File

lib/phases/phase_a_ai_suggest.sh

Phase R — RESEARCH Web search + synthesis (parallel with T)

Summary

Conduct federated web research via Gemini on high-level PRD gaps (missing features, architectural questions, security requirements). Claude then synthesizes findings into story descriptions. Runs in parallel with Phase T for efficiency.

Inputs

  • PRD gaps and epic descriptions
  • Search queries derived from missing features and stakeholder feedback
  • .spiral/research_cache.jsonl (optional) — Cached results to avoid re-searching

Outputs

  • Research story candidates with _source: "research", description, and _enrichment.research_source
  • Updated .spiral/research_cache.jsonl with TTL-based caching

Configuration Variables

  • SPIRAL_RESEARCH_ENABLED — Enable/disable research phase (default true)
  • SPIRAL_RESEARCH_CACHE_TTL — Cache time-to-live in hours (default 24)
  • SPIRAL_CONTEXT_BUDGET_TOKENS — Token limit for research synthesis (default 180000)

Implementing File

lib/phases/phase_r_research.sh / lib/phases/phase_r.py

Phase T — TEST SYNTH Test failure regression analysis (parallel with R)

Summary

Scan test-reports/ for failing tests, analyze root causes, and synthesize regression story candidates to fix each failure. Highest priority source — test-fix stories are merged before research or ai-example stories.

Inputs

  • test-reports/ — JSON/XML test result files from last validation
  • Code being tested — For context on what failed

Outputs

  • Regression story candidates with _source: "test-fix" and root-cause analysis
  • High priority — merged before research or ai-example stories

Configuration Variables

  • SPIRAL_VALIDATE_CMD — Test command to run (e.g., uv run pytest tests/ -v)
  • SPIRAL_TEST_BASELINE_CMD — Baseline performance threshold command

lib/phases/phase_t_test_synth.sh

Phase S — STORY VALID Validation & deduplication

Summary

Validate stories from Phases A/R/T against the project constitution, goal alignment, and deduplication rules. Duplicate stories are merged, and invalid stories are rejected. Output is a set of validated stories ready for enrichment.

Inputs

  • Story candidates from Phase A (ai-example), Phase R (research), Phase T (test-fix)
  • constitution.md — Non-negotiable rules for acceptance
  • prd.json goals — For alignment checking

Outputs

  • .spiral/_validated_stories.json — Deduplicated, validated stories
  • Rejection reasons logged for failed stories

Configuration Variables

  • SPIRAL_SPECKIT_CONSTITUTION — Path to constitution.md
  • SPIRAL_DEDUP_CONFIDENCE_THRESHOLD — Similarity threshold for dedup (default 0.75)

Implementing File

lib/phases/phase_s_story_validate.sh

Phase E — ENRICHMENT Populate hints & context

Summary

Populate each validated story with enrichment hints: similar passed stories as references, recommended implementation strategies, historical pass rates for model selection, and expected complexity. Prepares stories for efficient implementation.

Inputs

  • .spiral/_validated_stories.json — Validated stories from Phase S
  • results.tsv — Historical attempt data for pattern matching
  • prd.json — Full story history for reference solutions

Outputs

  • Enriched stories with _hints, _enrichment, _reference_implementations, and _antiPatterns fields
  • Ready for efficient Phase I implementation

Configuration Variables

  • SPIRAL_ENRICHMENT_ENABLED — Enable enrichment (default true)
  • SPIRAL_REFERENCE_IMPLEMENTATION_COUNT — Number of similar solutions to include (default 3)

Implementing File

lib/phases/phase_e_enrich.sh

Phase M — MERGE Update prd.json atomically

Summary

Merge enriched stories into prd.json following strict priority order: test-fix > research > ai-example. Respects SPIRAL_MAX_PENDING cap to prevent queue growth. Each merge is logged with timestamp and source for traceability.

Inputs

  • Enriched stories from Phase E (organized by priority: test-fix, research, ai-example)
  • prd.json — Current state to patch

Outputs

  • Updated prd.json with merged stories, atomic write via temporary file
  • .spiral/_merge_log.jsonl — Audit trail of each merge operation

Configuration Variables

  • SPIRAL_MAX_PENDING — Story cap before merge pauses (default 20)
  • SPIRAL_MERGE_STRATEGY — Merge ordering: priority-first (default) or round-robin

Phase I — IMPLEMENT Parallel story execution

Summary

Ralph worker processes execute stories in parallel using isolated git worktrees. Each worker calls Claude CLI with the story spec, commits results, and reports to results.tsv. Failure-aware retry: syntax errors same model + hint, context overflow → decompose, timeouts → escalate.

Inputs

  • prd.json (sliced) — Each worker gets a PRD slice with 1-3 pending stories
  • Context from Phase X (optional) — Symbol maps, dependency info
  • ralph/CLAUDE.md — Agent prompt for Claude CLI

Outputs

  • results.tsv — One row per story attempt: model, status, tokens, cost, duration, error_type
  • Git commits on per-worker branches (merged back to main in Phase P)
  • .spiral/worker_crashes.jsonl (optional) — Crash logs if workers fail

Configuration Variables

  • SPIRAL_MODEL_ROUTING — Model selection: auto (haiku→sonnet→opus), fixed, or historical (default auto)
  • SPIRAL_WORKER_POOL — Enable worker pooling (default true)
  • SPIRAL_VALIDATE_CMD — Quality check command (defaults to pytest)
  • SPIRAL_CONTEXT_WINDOW_MARGIN — Safety margin for context overflow (default 0.85)
  • SPIRAL_DECOMPOSE_THRESHOLD — Files per story before auto-decompose (default 3)

Implementing File

lib/phases/phase_i_implement.sh / ralph/ralph.sh

Phase V — VALIDATE Quality gates & test ratchet

Summary

Run the full test suite and quality gates: pytest coverage (minimum 48%), security scan (gitleaks), performance baseline, and test ratchet (never decrease passing tests). Stories that fail gates are reverted and retried in Phase I.

Inputs

  • Git commits from Phase I workers
  • results.tsv — Story outcome data
  • .spiral/test_baseline.txt (optional) — Previous passing test count

Outputs

  • .spiral/validation_report.json — Pass/fail for each gate with details
  • Updated .spiral/test_baseline.txt — Current passing test count
  • Reverted commits for failed stories (stored for retry analysis)

Configuration Variables

  • SPIRAL_VALIDATE_CMD — Test command (default: uv run pytest tests/ -v --tb=short -n 6)
  • SPIRAL_VALIDATE_TIMEOUT — Test execution timeout in seconds (default 600)
  • SPIRAL_TEST_BASELINE_CMD — Baseline performance check
  • SPIRAL_SECURITY_SCAN_ENABLED — Run gitleaks scan (default true)

Implementing File

lib/phases/phase_v_validate.sh / lib/phases/phase_v.py

Phase C — CHECK DONE Completion assessment

Summary

Assess loop completion: count passed vs pending stories, check cost ceiling and time limits, generate summary report. Exit if all stories pass or limits hit; else loop back to Phase A for next iteration.

Inputs

  • prd.json — Current state with story status (passes: true/false)
  • results.tsv — Accumulated cost and attempt data
  • Time elapsed since start

Outputs

  • .spiral/completion_report.json — Pass count, fail count, pending count, total cost, reason for exit
  • Exit decision: continue loop (Phase A) or exit gracefully

Configuration Variables

  • SPIRAL_COST_CEILING — Maximum USD cost per run (default unlimited)
  • TIME_LIMIT_MINS — Maximum duration in minutes (0 = unlimited)

Implementing File

lib/phases/phase_c_check_done.sh

Phase L — LEARNING Episodic memory extraction

Summary

Extract patterns and success/failure modes from results.tsv and git history. Learn which story types (complexity, source, model) have highest success rates. Store episodic memory for future iterations to make better model routing and decomposition decisions.

Inputs

  • results.tsv — Complete attempt history: model, status, complexity, source
  • prd.json — Story metadata and dependency info
  • Git log — For context on implementation patterns

Outputs

  • .spiral/episodic_memory.jsonl — Pattern records: story similarity, success rate by complexity/model, anti-patterns
  • learning.md — Human-readable summary of insights

Configuration Variables

  • SPIRAL_EPISODIC_MEMORY — Enable memory extraction (default true)
  • SPIRAL_LEARNING_MIN_SAMPLES — Minimum attempts before pattern learned (default 3)

Implementing File

lib/phases/phase_l_learn.sh
