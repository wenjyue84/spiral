09 Troubleshooting

Common issues, exit codes, and recovery procedures

Known Issues & Solutions

Search for your symptom below. Click any row for more details.

Symptom Cause Fix
All stories done but Spiral keeps running Expected behavior — Phase R discovers new stories each iteration Set --until HH:MM or --time-limit N to stop at a specific time
Tests failing immediately Validation command is incorrect or failing Check SPIRAL_VALIDATE_CMD in spiral.config.sh
Workers not merging cleanly Merge conflicts during parallel execution Reduce --ralph-workers to 1
Research phase slow or unhelpful Too many stories queued or broad scope Add --skip-research, reduce --capacity-limit, or set SPIRAL_FOCUS
OOM / out of memory Workers using too much memory Reduce --ralph-workers, lower SPIRAL_WORKER_MEMORY_LIMIT, or set SPIRAL_PREEMPTIVE_PRESSURE_MB
Story keeps failing (3 retries) Story is too large or has unmet dependencies Auto-decomposes into sub-stories; or rollback with --rollback STORY_ID
Story too expensive Complex story consuming many tokens Lower SPIRAL_STORY_COST_HARD_USD; use --model haiku
Dashboard not opening Dashboard disabled in config Set SPIRAL_OPEN_DASHBOARD=1 in spiral.config.sh
Firecrawl errors Missing or invalid API key Verify FIRECRAWL_API_KEY env var is set
GitNexus not annotating GitNexus not initialized Run gitnexus analyze first in the repo
prd.json corrupted after crash Incomplete write during crash Auto-restored from .spiral/prd-backups/prd-iter*.json; no manual fix needed
Stale spiral-worker-* branches Leftover branches from crashed workers Auto-purged on next run startup
index.lock blocking git ops Git lock file from previous crash Auto-removed before worktree creation on next run
Phase T hanging Test synthesis taking too long Default 60s timeout auto-kills it; set SPIRAL_TEST_SYNTH_TIMEOUT to adjust
Deferred workers never launch Memory pressure preventing worker spawning Check memory pressure — stalls warn after SPIRAL_QUEUE_STALL_WARN_SECS (600s)
.rej files after parallel run Patch conflicts during merge Check spiral_events.jsonl for patch_rejected events; delete .rej files manually
Wrong time in iteration calculation System time used instead of AI estimate Run date "+%H:%M" manually — the skill uses real system time
prd.json.lock blocking workers Stale lock file from crashed worker Lock includes PID; stale locks auto-broken on next acquisition. Manual: rm prd.json.lock
Duplicate stories after crash Incomplete merge transaction Transaction journal auto-recovers on next iteration; check .spiral/_txn_journal.jsonl
Worker idle while others have stories No work-stealing enabled Set SPIRAL_WORK_STEALING=true in spiral.config.sh to enable work-offering queue

Exit Codes Reference

SPIRAL returns these exit codes to indicate the final state of a run.

Code Meaning
0 Success — all stories pass + tests clean
2 Bad CLI arguments
3 Missing or invalid spiral.config.sh
4 Required tool not found (jq, claude, etc.)
5 prd.json not found
6 prd.json corrupted and unrecoverable
7 prd.json schema version too new
8 Cost ceiling exceeded
9 Zero-progress limit reached (stuck)
10 --replay mode: story failed
11 --replay mode: story ID not found
12 --rollback mode: git revert failed
13 Max iterations reached; stories still remain
14 Claude API unreachable at startup probe
15 Consecutive story failures exceeded cascade fan-out limit
130 Interrupted by Ctrl+C (checkpoint saved, run again to resume)

Crash Recovery & Auto-Healing

SPIRAL includes built-in recovery for common failure scenarios. Most issues are automatically repaired on the next run.

Failure Auto-Recovery
prd.json corrupted mid-write Validated with jq empty each iteration; restored from latest .spiral/prd-backups/prd-iter*.json
Interrupted run (Ctrl+C) Checkpoint saved at last completed phase; re-run to resume from where it stopped
OOM-killed worker leaves index.lock Removed before worktree creation on next run
OOM-killed worker leaves prd.json.lock PID written to lock file; stale locks (dead PID) auto-broken on next acquisition attempt
Orphaned spiral-worker-* branches Auto-deleted at startup if not in any live worktree
Phase T hangs Killed after SPIRAL_TEST_SYNTH_TIMEOUT seconds (default 60s); empty output used as fallback
Crash between overflow + prd.json writes (Phase M) Write-ahead transaction journal (_txn_journal.jsonl) rolls back incomplete multi-file writes on next iteration startup
Stuck story never requeued Force-reset if .passes not correctly set to false; check heartbeat log
/tmp fill-up from previous runs Temp files cleaned on startup
Deferred worker queue stalled Warns with actionable message after SPIRAL_QUEUE_STALL_WARN_SECS (default 600s)
Worker finishes early, sits idle SPIRAL_WORK_STEALING=true enables finished workers to claim uncompleted stories from a shared queue
Parallel worker retry counts lost Per-worker retry-counts.json merged back to root after each parallel wave
Locked worktrees block all workers Worktrees locked by crashed runs resist --force removal. Auto-handled by run_parallel_ralph.sh since 2026-03-20
Auto-stash reverts uncommitted config changes spiral.sh auto-stashes dirty files before Phase I, then pops after. Fix: commit config changes to git
Story timeout too short for complex stories Default medium=900s insufficient for integration tests. Set in spiral.config.sh; recommended: small=1200s, medium=1800s, large=2400s
Corrupt story title (ID as title) Phase M occasionally assigns story ID as title. Fix: manually correct title in prd.json
