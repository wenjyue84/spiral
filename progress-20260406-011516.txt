**Subject: Technical Brief for US-1062: Story Validation Confidence Scorer**

This user story pertains to the 'Spiral' Python CLI tool, not a Frappe application. All recommendations apply to the Python project structure shown.

**1. Python Files to Modify:**
*   **New File:** `lib/story_validation_scorer.py`. This will contain the core logic for parsing and scoring stories from `prd.json`.
*   **Existing File:** `main.py`. This file likely handles argument parsing and subcommand dispatching. It will need to be modified to add the new `score-stories-for-validation` command and call the new scorer module.

**2. Frappe DocTypes/Hooks Involved:**
*   None. This is a Python CLI tool. The primary data structure is the `prd.json` file, which will be read and modified in-place.

**3. Recommended Implementation Approach:**
1.  In `lib/story_validation_scorer.py`, create a function that takes the contents of `prd.json` as input.
2.  This function will iterate through each story, calculating a `_validation_confidence` score (0-100).
3.  The score starts at 100 and is reduced based on:
    *   Presence of complexity keywords in the `description` (e.g., 'database', 'concurrency').
    *   A penalty of 5 points for each dependency in the `dependency_count`.
    *   A penalty of 10 points for complex regex/patterns in `file_change_hints`.
4.  Update the story object in-memory with the new `_validation_confidence` field.
5.  In `main.py`, add the CLI subcommand which loads `prd.json`, calls the scoring function, and overwrites `prd.json` with the returned result.

**4. Edge Cases & Gotchas:**
*   **Data Safety:** The script must create a backup of `prd.json` before overwriting it to prevent data loss on error.
*   **Heuristics:** The scoring weights for keywords and the definition of "complex patterns" in `file_change_hints` are not fully specified and will require reasonable heuristics.
*   **Schema Errors:** The script should gracefully handle missing keys (e.g., `dependencies`) in the story objects within `prd.json`.
