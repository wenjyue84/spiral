## Iteration [Current] - Story: US-650 CLI: spiral cost-forecast

### What was implemented
- **lib/cost_forecast.py** — New module for velocity-based cost forecasting
  - `load_results(path)` — reads results.tsv into row dicts
  - `compute_velocity(rows, last_n_iterations=5)` — computes story completion velocity and token cost velocity from last N iterations
  - `forecast(prd_path, results_path, last_n=5)` — returns {remaining_stories, iterations_needed, projected_cost, confidence_pct}
  - Confidence scales linearly with available iterations vs requested window (0% at 0, 100% at last_n+)

- **main.py** — Added `cost-forecast` subcommand
  - `spiral cost-forecast [--prd FILE] [--results FILE] [--last-n N]`
  - Outputs JSON: {remaining_stories, iterations_needed, projected_cost, confidence_pct}
  - Added subparser, dispatch branch, and `cmd_cost_forecast()` handler

- **tests/test_cost_forecast.py** — 10 tests across TestComputeVelocity and TestForecast
  - Key: test_basic_10_iteration_forecast confirms ±20% accuracy against ground truth

### Patterns discovered
- results.tsv token columns: cache_read_tokens + cache_creation_tokens + review_tokens = total
- PASS_STATUSES = {"keep", "pass", "success"} — "reject" rows excluded from velocity
- Rejected story tokens ARE counted in cost_velocity (they still consume API budget)
- Confidence calculation: completed_iterations / last_n * 100, capped at 100%

### Gotchas
- Windows Python requires `encoding='utf-8'` on all file opens (cp1252 crash)
- mypy strict requires `dict[str, float | int]` return type (not just dict)
- Pre-existing mypy failures exist in token_guard.py and batch_validate.py — not related to this story

### Acceptance Criteria Mapping
1. ✅ CLI outputs JSON with {remaining_stories, iterations_needed, projected_cost, confidence_pct}
2. ✅ Computation uses velocity = completed/iterations and cost_velocity = tokens/iterations
3. ✅ Integration test with 10 mock iterations asserts within ±20% of ground truth

## Iteration [Previous] - Story: US-646 Model Escalation Explainability Report

### What was implemented
- **lib/impl/escalation_tracker.py** — New module to track and categorize model escalations
  - `detect_reason_code()` — Analyzes stderr output to identify escalation reason (token_limit, syntax_error, timeout, api_error)
  - `write_escalation()` — Writes escalation entries to .spiral/escalations.json
  - CLI interface for logging escalations from Ralph retry logic
  - Handles empty/missing data gracefully with sensible defaults

- **spiral-ui/server.ts** — Added REST API endpoint
  - GET /api/dashboard/escalation-breakdown — Returns categorized counts of escalations by reason code
  - Reads .spiral/escalations.json and aggregates counts
  - Returns {token_limit, syntax_error, timeout, api_error, total_escalations}
  - Gracefully handles missing escalations file (returns zeros)

- **tests/test_escalation_tracking.py** — Comprehensive test suite with 10 tests
  - TestDetectReasonCode: 6 tests covering all reason code detection patterns
  - TestWriteEscalation: 3 tests for file I/O and appending behavior
  - TestEscalationBreakdown: 1 integration test with 3 mock failures (token_limit, syntax_error, timeout)
  - All tests use pytest fixtures and tmp_path for isolation

### Patterns discovered
- The project uses .spiral/ as the scratch directory for runtime artifacts
- spiral-ui runs on port 5299 with Express/TypeScript server
- Escalation entries include: story, attempt, model_used, reason, tokens_used, retry_model, timestamp (ISO8601 UTC)
- Reason codes form a closed set (validated enum): token_limit, syntax_error, timeout, api_error
- Tests follow pytest patterns with class-based organization and return type annotations (-> None)

### Gotchas
- Windows Python requires `encoding='utf-8'` on all file operations to avoid cp1252 crashes
- mypy strict mode requires explicit return type annotations on all functions/methods
- Ruff lint checks for unused imports (must remove os import if unused)
- The escalations.json file is created on first write; endpoint gracefully handles missing file

   - Implemented via `write_escalation()` with {story, attempt, model_used, reason, tokens_used, retry_model, timestamp}
