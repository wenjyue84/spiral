## Iteration [Current] - Story: US-655 Dashboard Endpoint: GET /api/dashboard/retry-analysis

### What was implemented
- **lib/retry_analysis.py** — New module for computing retry statistics from results.tsv
  - `load_results(path)` — reads results.tsv into row dicts
  - `compute_retry_stats(results) -> dict[phase][count/mean/median/max/retry_rate/story_count]` — aggregates retry counts by phase
  - `compute_retry_rates(results) -> list[{phase, retry_rate, story_count}]` — returns phases sorted by retry_rate descending

- **spiral-ui/server.ts** — Added REST endpoint
  - GET /api/dashboard/retry-analysis
  - Reads results.tsv and computes per-phase retry statistics
  - Returns JSON with {phases: [...stats...], retry_rates: [...sorted...], total_stories, total_retries}
  - Gracefully handles missing results.tsv file (returns empty response)

- **tests/test_retry_analysis.py** — 16 comprehensive tests across 4 classes
  - TestLoadResults: 3 tests (missing file, empty file, single row)
  - TestComputeRetryStats: 6 tests (empty, single phase, multi-phase, missing phase, invalid retry_count, retry_rate calc)
  - TestComputeRetryRates: 4 tests (empty, single phase, sorted descending, required fields)
  - TestRetryAnalysisIntegration: 3 tests (15 stories across 6 phases, zero retries, high retries)

### Patterns discovered
- results.tsv uses `retry_count` column (integer); parsed from TSV with fallback to 0 on error
- Phase names in results.tsv are uppercase (R/T/S/M/I/V); missing phase field defaults to "UNKNOWN"
- Retry rate formula: total_retries_in_phase / stories_in_phase (can exceed 1.0 for phases with many retries)
- spiral-ui endpoint pattern: read file, parse JSON/TSV, aggregate, return JSON with graceful fallback for missing files

### Gotchas
- Windows Python requires `encoding='utf-8'` on all file opens
- mypy strict mode requires explicit return types; unused `type: ignore` comments trigger errors
- retry_count parsing must handle missing/invalid values gracefully (default to 0)
- Statistics module (mean/median) requires non-empty list; early guard for empty stats

### Acceptance Criteria Mapping
1. ✅ Endpoint queries results.tsv, calculates retry_count distribution grouped by phase
   - Implemented in spiral-ui/server.ts endpoint, reads results.tsv and aggregates by phase
2. ✅ Response includes per-phase retry rates (total_retries/total_stories) sorted descending
   - compute_retry_rates() returns sorted list with {phase, retry_rate, story_count}
3. ✅ Test mocks results.tsv with 15 stories across phases with varying retry counts
   - TestRetryAnalysisIntegration::test_integration_15_stories_across_phases validates full aggregation

## Iteration [Previous] - Story: US-650 CLI: spiral cost-forecast

### What was implemented
- **lib/cost_forecast.py** — New module for velocity-based cost forecasting
  - `load_results(path)` — reads results.tsv into row dicts
  - `compute_velocity(rows, last_n_iterations=5)` — computes story completion velocity and token cost velocity from last N iterations
  - `forecast(prd_path, results_path, last_n=5)` — returns {remaining_stories, iterations_needed, projected_cost, confidence_pct}
  - Confidence scales linearly with available iterations vs requested window (0% at 0, 100% at last_n+)

- **main.py** — Added `cost-forecast` subcommand
  - `spiral cost-forecast [--prd FILE] [--results FILE] [--last-n N]`
  - Outputs JSON: {remaining_stories, iterations_needed, projected_cost, confidence_pct}
  - Added subparser, dispatch branch, and `cmd_cost_forecast()` handler

- **tests/test_cost_forecast.py** — 10 tests across TestComputeVelocity and TestForecast
  - Key: test_basic_10_iteration_forecast confirms ±20% accuracy against ground truth

### Patterns discovered
- results.tsv token columns: cache_read_tokens + cache_creation_tokens + review_tokens = total
- PASS_STATUSES = {"keep", "pass", "success"} — "reject" rows excluded from velocity
- Rejected story tokens ARE counted in cost_velocity (they still consume API budget)
- Confidence calculation: completed_iterations / last_n * 100, capped at 100%

### Gotchas
- Windows Python requires `encoding='utf-8'` on all file opens (cp1252 crash)
- mypy strict requires `dict[str, float | int]` return type (not just dict)
- Pre-existing mypy failures exist in token_guard.py and batch_validate.py — not related to this story

### Acceptance Criteria Mapping
1. ✅ CLI outputs JSON with {remaining_stories, iterations_needed, projected_cost, confidence_pct}
2. ✅ Computation uses velocity = completed/iterations and cost_velocity = tokens/iterations
3. ✅ Integration test with 10 mock iterations asserts within ±20% of ground truth

## Iteration [Current] - Story: US-651 Phase R Query Similarity Deduplication

### What was implemented
- **lib/research_dedup.py** — New module for TF-IDF-based query similarity deduplication
  - `query_similarity(q1, q2) -> float` — TF-IDF cosine similarity via sklearn; identical=1.0, orthogonal≈0.0
  - `find_cached_response(query, cache_path, threshold) -> dict | None` — iterates .spiral/research_cache.json, returns best entry above threshold
  - `SPIRAL_RESEARCH_DEDUP_THRESHOLD` — configurable via env var (default 0.85)
  - CLI: `python lib/research_dedup.py --query QUERY [--threshold N] [--cache-path PATH]` (exit 0=hit, 1=miss)

- **lib/phases/phase_r_research.sh** — Added dedup check between topic-level exact cache and Gemini call
  - If exact cache misses, checks .spiral/research_cache.json (or scratch copy) for similarity match
  - On hit: reuses cached gemini_research, sets _RESEARCH_TOPIC_CACHED=1, logs research_dedup_hit event

- **tests/test_research_dedup.py** — 14 tests across 3 classes
  - TestQuerySimilarity: 6 tests (identical=1.0, empty=0.0, similar high, dissimilar low, symmetric, unit interval)
  - TestFindCachedResponse: 6 tests (no file, empty cache, high-sim hit, low-sim miss, corrupt, best-of-N)
  - TestResearchDedupCostTracking: 2 tests verifying dedup hit skips mock Gemini call

### Patterns discovered
- research_cache.json entries have: {topic, result, fetched_ts, expires_at}; result is a dict (usually {gemini_research: ...})
- Phase R uses _RESEARCH_TOPIC_CACHED to gate the Gemini call; set it to 1 to skip
- TF-IDF is sufficient for dedup; no need for sentence-transformers at this integration point
- sklearn TfidfVectorizer raises ValueError on empty vocabulary (handled with try/except → 0.0)

### Gotchas
- lib/research_dedup.py mypy strict passes because sklearn imports are inside function body (lazy)
- ruff isort: put sys.path.insert BEFORE local imports in test files
- Test thresholds for TF-IDF similarity need to be 0.4-0.5 (not 0.85) to get reliable hits in unit tests
